    METHODOLOGY & TRANSPARENCY

    Built to be explainable.

    A compact demonstration of ML deployment, model voting, and transparent results.

    Detection workflow

    What happens when you submit a transaction.

    1
    Collect the inputs

    Amount (INR) and local timestamp are validated on the client and server.

    2
    Prepare features

    Log-transformed amount and cyclical hour features are passed through the trained preprocessing pipeline.

    3
    Run the ensemble

    Isolation Forest, One-Class SVM, and XGBoost each output an independent binary signal.

    4
    Apply a majority vote

    At least two anomaly votes yield an elevated assessment. The result is not a fraud probability.

    Model cards

    Different modeling approaches, one consensus.

    Isolation Forest

    Unsupervised anomaly detection trained on simulated routine transactions.

    One-Class SVM

    Learned normal-behavior boundary using scaled synthetic transaction features.

    XGBoost

    Supervised classifier trained with generated synthetic labels.

    Limitations and responsible use

    This project is an educational proof of concept. It has not been trained or validated with real bank transaction records. Transaction amount and time are insufficient for reliable UPI fraud detection. The output is not evidence of a crime, cannot verify a recipient, and must not be used to automatically block payments. Never provide a UPI PIN, OTP, password, or complete banking credentials. If you suspect fraud, contact your bank promptly and use official reporting channels.
